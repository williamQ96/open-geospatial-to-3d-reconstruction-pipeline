# 骨骼角色、校园活动和室外导航

[English](campus-life-navigation.md) | **简体中文**

浏览器模板增加可选骨骼角色、统一四档密度滑块（默认 Mid），以及基于室外路径图的导航。UO 的具体素材、配色、路线和停车位置仍由下游维护。

Overview 要求 A／B，可复用建筑搜索或在地图建筑外空地选点；第一／第三人称在点击 Start route 时保存角色位置为固定起点。行走和切换这两种视角时，起点圆点与完整路线保持固定，仅更新角色定位、箭头和到达检测。再次 Start route 重新保存起点，Clear／重选端点重置。返回 Overview 恢复手动 A 或重新询问，返回步行视角恢复其保存的起点，不传送角色。蓝色路线和实例化白色箭头沿 A→B 流动，小地图同步显示；关闭面板保留路线。选点面板会折叠，方便手机操作。

`build_navigation_graph(features, buildings, step_m=7)` 将道路／步道交点连接，排除缓冲后的建筑内部，只在无建筑阻挡的短距离间隙加入推测连接。建筑搜索停在附近室外接近点，不假设真实入口；不保证无障碍、当前通行、施工或开放时间。

骨骼资产导入时必须验证绑定姿态和动画骨架的静止姿态。姿态不同时，应把源骨架世界矩阵烘焙为目标骨架局部动画，避免直接复制 action 导致 T pose。保留原包、许可证据、校验值、使用的贴图和可编辑的 Blender 文件。CC0 基础素材保持 CC0，原创添加部分单独署名；使用中性服装配色，避免校徽和 mascot。

NPC／交通是固定路线往返的示意活动，不是实时模拟，使用胶囊体对角色、道具和其他 NPC 停止让行；骑行姿态为简化原创造型。车辆使用合并的顶点着色几何减少 draw call，支持 GLB 导出和 Blender 编辑。No 档移除全部氛围对象与碰撞体；动态物体不写入静态阴影缓存。应分别验证沉浸模式和纯净地图性能。

首轮允许合理推测，优先形成完整、可辨识且可维护的闭环，精度和写实通过长期纠正提升。完整接口、测试与 UO 示例见英文文档。

当前推荐统一 No / Low / Mid / High 密度滑块（默认 Mid），代替独立开关。可选松鼠、声音、脚步、轻微晃动与反馈的接口见[氛围交互](zh-CN/ambient-interaction.md)。配合[尽早可交互的迭代循环](zh-CN/iterative-community-modeling.md)。

当前本地活动接口升级到 version 2，导航图仍为 version 1；先迁移旧活动数据，再同步运行时。见[语义活动与模板](zh-CN/semantic-activity.md)、[一级 Beta](zh-CN/beta-functions.md)及 [Zombie 模板](beta/zombie-school.zh-CN.md)。
