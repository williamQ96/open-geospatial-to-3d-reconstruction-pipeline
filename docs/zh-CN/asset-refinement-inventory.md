# 资产清单与分治细化

在各下游项目维护清单，按区域、建筑和资产类型划分工作，再选取资料较充分的建筑或边界明确的一批资产进行细化。连接可编辑源文件、运行资产、证据、未知事项及下一步；验证后再更新记录。保留人工修改，不用自动白膜覆盖权威资产。这是规划和证据方法，不是测绘证明或自动验收。

## 等级及适用范围

用户目前定义 **0 级为仅白膜，1 级为简单渲染**。首个下游项目的 Knight Library 外部被用户单独指定为 **2 级示例**；不能由此推导通用 2 级标准，也不能给相似资产自动赋 2 级。**3–5 级保留，等待用户颁布标准**，不擅自定义或视为批准。空白表示未评级或不适用；计划资产不因存在占位物或共用模板而自动获得 0、1 级。

首个下游用户把其余现有部分指定为 1 级基线；这是该项目的指令，不是其他项目的自动评估。其他现有资产在负责人指定之前可以留空。等级不证明身份、尺寸、资料来源、无障碍或现状准确性。

## 创建与维护

将[仅含表头的 CSV 模板](../../templates/asset-refinement-inventory.csv)复制到下游。支持 UTF-8 或带 BOM 的 UTF-8。逐项或按合理组填写唯一 `asset_id`、`area` 区域、`asset_type` 类型、`name`、`status`（`existing` 现有或 `planned` 计划）、`level`、`evidence` 证据、`next_refinement` 下一步和 `unknowns` 未知事项。建筑外部、共用室内模板和每栋建筑尚未创建的独立内部应分行；共用教室不能算作每栋建筑已有专属内部。计划条目的等级留空，未命名候选及非官方制作分区须明确标注。建筑 ID 拆分、合并或变更时保留映射与历史。

在母仓库运行 `python scripts/check-asset-inventory.py path/to/inventory.csv`，可检查表头、必填字段、ID 唯一性、状态和等级范围及计划资产未评级。空模板可通过；已有下游清单若使用中文或描述性状态，须先明确映射为 `existing` / `planned`，迁移时保留原始记录及语义。工具**不验证**文件、许可、场景 ID 对应关系、真实性或等级是否合理。下游须自行核对清单与场景、来源及统计，并保留检查记录。用户制定 3–5 级标准后再更新校验器。

## 分治循环

1. 盘点现有与计划资产，对照场景 ID，分别统计已命名与未识别候选；候选不一定是一栋真实建筑。
2. 按区域、建筑和类型分批，结合证据、重要性、依赖与未知程度决定优先顺序。
3. 收集许可明确、有日期的资料，区分观察、推断和遮挡；保留坐标、ID、风格、碰撞及源文件历史。
4. 编辑源文件，仅重建受影响的交付层；保留无关改动与人工模型。
5. 核查 ID、证据和许可、几何与导出，并在场景中检查位置和材质；记录真实完成的验证及局限。
6. 更新受影响的行、证据、状态与下一步；仅按用户标准或明确指定调整等级，分别记录发布状态。
