# 低成本风格化资产方法

这是供人与下游项目选用的交付约定，并非机器验证的 schema；不会替代地理 schema v1、来源记录、参考媒体审计或模板锁。它不会自动生成、验证、转换或托管资产。[英文版含示例记录](../asset-method.md)。

1. 明确用途、目标平台、风格、预算和可接受的不确定性；优先保留可编辑源文件。
2. 按问题选择 GIS、点云、照片、图纸、开放数据与资产、原创研究或概念描述。人工、程序、技能和 AI 可辅助制作。使用前检查复制、修改、再分发、署名及服务条款；网上可见或 AI 生成不等于已取得权利。权利不明确时先解决再发布。
3. 区分测量、解释和虚构；记录作者、日期、来源、许可证据、访问日期、允许保存的副本和校验值。生成内容尽可能记录工具版本、输入、参数或提示、修改及局限；生成过程不证明准确性或权属。
4. 按目标设定配色、比例、材质和性能预算；在实际设备上测试，逐步细化。概念示意不必声称物理精确。
5. 保存可编辑源文件，按消费者需要交付 GLB/glTF 或程序化源代码等；适用时记录单位、轴、原点、依赖和许可。不同引擎的格式与材质支持不同，需要在实际消费者中验证。
6. 将制品、署名、许可和交付记录放在一起。由下游选择静态站点或存储服务，核验路径、跨域、缓存、版本、大小与署名；服务、可用性和成本由运营者负责。上游目前不提供托管服务。
7. 在目标设备检查加载、呈现、交互与资源释放，记录缺陷并保留版本和来源；不要静默覆盖人工精修的原件。

Open Campus: UO 继续使用地理导出、来源记录和两种锁；Open Philosophy 使用自己的 Three.js 场景和引用，目前不消费上游地理格式或模板。新增通用验证器、适配器、跨消费者示例和托管自动化均属未来工作，现有流程无需迁移。
