# 先建立可辨识的场景，再长期纠正

首轮建模应交付完整、可辨识、可编辑的场景，**不把照片级写实或完整测绘证据作为发布第一轮的前提**。缺失的立面、重复细节、屋顶、植被和材质允许合理推测，只要明确标注、易于替换。精细程度与真实程度通过长期纠正和维护逐步提高。

这是制作主张，不把生成的细节冒充测量。地理证据与外观分离，保留已知坐标、历史日期、稳定 ID 和重建记录。说明观察到了什么、推测了什么、后续什么证据能纠正它；mockup 是画风参考，不是地理来源。

## 低成本混合方法

用已有核验地形／LiDAR 或明确的近似包络定位置和尺度；归档照片识别建筑特征；开放且有地理参考的航拍引导景观分布；共享简单材质统一画风。以后可以用实测替换估算；没有实测就明确记录。总体包络有依据，不等于每个细节都准确。

把建筑分解为可复用的**建筑语法**：窗格、楼层带、柱廊、檐口、台阶、雨棚、入口。数量、间距与尺寸留在可编辑参数中，以干净网格和标准 PBR 导出，再做渲染风格适配。稀疏且跨年份的参考照片不必强行进行密集重建，也不必生成巨型照片贴图。

有重叠和移动视差的手机照片／视频、手机深度、少量尺寸控制、摄影测量或 splat 可作为后续采集路线，本次没有实现或评估它们。按需要解决的具体疑问选择，分别检查工具代码、模型权重和输入许可，不把程序化参考建模说成实测、摄影测量或 AI 几何求解。

## v0.6 已实现的方法

[`architectural.facade_modules`](../../src/geospatial3d/architectural.py) 接收本地 ENU 米制立面线段、重复数量、楼层高度、两端留白和外向偏移，返回组件中心、朝向与格宽。Blender 下游可在这些位置实例化自己的窗／门／柱模块。局部 X 沿线段，局部 -Y 指向右侧外部，反转线段即可反向。退化、无效参数明确失败，不偷偷生成几何。UO 用于图书馆高窗、六柱柱廊和 EMU 重复玻璃；具体模块、尺寸和材质仍在下游。

[`canopy_cues`](../../src/geospatial3d/canopy_cues.py) 使用暗色、有纹理的绿色 RGB 区域生成平滑分布线索，并在明确同一坐标框架的北向上图像中采样。UO 使用固定日期和 raster ID 的 NAIP 裁剪，叠加建筑／道路退让、开敞草坪、出生视线和种子化间距，放置风格化树木。

这**不是经过独立验证的单株树木检测器**，可能混淆阴影、草和灌木；树干、树高、冠幅和树种仍为美术推测。它不做 CRS 转换、不从 RGB 求树高，也不保证当前现状。须保留原图、范围、CRS、分辨率、日期、源 raster、导出请求和 hash。PNG 无内嵌地理参考时使用导出记录，不能仅凭尺寸猜坐标。

## 发布与长期修正

首轮验收看场景是否连贯、地标是否可辨识、远近是否可读、Blender／GLB 是否可编辑导出、来源能否开放复用，以及三视角／搜索／标签／小地图／移动是否保持可用。明确说明的不确定细节不阻断首版。记录设备相关成本，软件渲染时间不能冒充硬件性能。

每组特征记录来源 ID、观察特征、推测尺寸／遮挡面、日期／状态、可编辑参数和下一条有价值的纠正。优先解决身份、轮廓、入口、尺度和交互问题，再逐步追求微小表面写实。重生成前保留手工修改；外观可信不代表新获得了地理、碰撞或通行证据。

第一份实际应用是 [UO v0.7](https://github.com/williamQ96/open-campus-uo/blob/main/docs/visual-refinement-v0.7.md)。合成测试覆盖立面间距／反向／参数、树冠线索与南北采样；下游验证真实资产和交互。这是一份有效首例，不等于测绘精度、通用 RGB 阈值或其他地区均已验证。见[素材规范](reference-media.md)、[美术层契约](presentation-layers.md)与[画风库](../../style/README.zh-CN.md)。

推荐[尽早可交互的社区迭代循环](iterative-community-modeling.md)：先形成可检查的交互，再通过用户反馈和开发者主动细化持续改进，保留地理证据与推测艺术细节的区别。
