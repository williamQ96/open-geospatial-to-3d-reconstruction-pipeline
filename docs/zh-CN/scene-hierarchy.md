# 推荐场景分层：重点、校园与背景

[English](../scene-hierarchy.md) | **简体中文**

**推荐制作标准：**重点场景投入照片参考和可辨识构件；次要场景继续存在并保持地理规划，用原创程序化构件或可开放导出的 low-poly 素材、固定随机外观、较少细节和空间雾化承担背景作用。它补充默认 Architectural Toon Realism 画风，作者仍可探索其他画风与分层方式。

| 层级 | 推荐做法 | 地理约束 |
| --- | --- | --- |
| 主要地标 | 从归档原照提炼体量、窗列、入口、屋顶、山花、拱窗、雨篷等语法，参数化建模 | 保留位置来源，区分照片观察与尺寸／隐藏面推测 |
| 主场景一般建筑 | 复用屋顶、窗格、材料和植被构件，优先风格统一与可读性 | 保留 ID、占地轮廓、高度依据、道路与街区规划 |
| 外围背景 | 原创或许可明确的开源 low-poly 构件，固定种子选择类型／配色，降低细节，雾化与降饱和度 | **随机外观，不随机建筑坐标**；按原轮廓定位、对齐和裁剪，不移动道路或覆盖街区 |

背景是次要场景，不是可丢弃的地理信息。类型可用住宅／低层楼／仓库等近似分类，但不得冒充真实用途。种子应依赖稳定 ID 而非数组顺序；单一区域重建不能让其他区域重新洗牌。优先级范围不构成产权或通行界线。

采用的图片和外部资产仍须归档：作者、许可版本、来源、原文件、时间、修改和校验值。优先 CC0 或兼容署名许可，保留第三方条款。素材不合适时，原创程序化构件也是快速、可开源导出的选择。照片用于提炼建筑语法，不要求照片贴图或逐像素复制；比例、数量、朝向与未见面允许合理推测，但应记录并便于长期纠正。

上游已有可复用实现：`context_appearance.appearance_plan` 固定种子且保留原始坐标／轮廓／高度记录；`pitched_roof_faces` 将坡屋顶裁剪到原占地；浏览器合批节点保留 `asset_ids`；Blender 按建筑独立编辑，运行时仅合并副本；`context-fog.js` 按固定世界区域在顶点计算雾化并插值，不依赖镜头跟随或额外模糊渲染；精确贴合高度场的景观可以声明 `heightfield_offset_m`，避免每帧遍历大量草地三角形。它不产生新的通行或无障碍依据。

文本来源保留构建时原始字节 hash，另加 UTF-8／无 BOM／LF 标准化 hash 处理跨平台换行。图片、模型等二进制仍逐字节校验，不改写历史来源。

验收应验证地理不变量、种子稳定性、屋顶包含关系、许可、可编辑源文件与 GLB；同时检查三视角、搜索标签、小地图、手机操作、导航与开关，并对比雾化前后。记录下载体积、draw call、内存与实际设备帧时；卡通或雾化并不自动更快，不能用雾隐藏缺失的道路规划。

当某个背景地块升级为主要目的地时，应保留身份与坐标，提升该区参考照片与模型细节。具体案例和素材只放下游，上游只记录通用方法；其他画风与实现继续受到鼓励。
