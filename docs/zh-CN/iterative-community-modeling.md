# 推荐开发循环：尽早可交互，共同迭代细化

[English](../iterative-community-modeling.md) | **简体中文**

尽早建立可以交互的初步阶段：地形和道路、白膜几何体建筑、简单角色与可用操作。让大家能实际探索、指出问题，再投入全面精细化。这是对社区友好的开放地图项目的推荐起点。

**可交互白膜 → 真实资料与明确记录的合理推测 → 连贯的中等精度建模 → 用户反馈或开发者主动细化 → 纠正并形成下一次可交互迭代 → 持续循环。**

地理测量、景深与归档照片各自提供其能够支持的证据，从中识别轮廓、屋顶和立面规律、材质家族与植被线索。遮挡立面、植物高度和装饰细节可以合理推测，但保持可编辑并与观测证据区分。首轮允许中等精度、风格化且连贯的结果，不以照片写实、全面测量或严格学术复刻作为交互与开放的门槛。改变外观时保留准确的坐标、占地、道路与街区。[场景分层](scene-hierarchy.md)帮助将精力集中于主场景，外围用较低成本与柔化处理服务背景。

欢迎社区反馈，也鼓励开发者主动改进。反馈可涉及模型、通行假设、名称、交互、性能或可访问性。记录迭代标识，可选位置，只收集理解问题所需的信息。具体反馈和开发日志归属于下游项目；可复用算法、交互规则与验证经验回流上游[方法论日志](../../METHODOLOGY_LOG.zh-CN.md)。

保持稳定身份、可编辑源、来源及不确定性说明，以便有意识地纠正推测。归档采用的照片与许可，使用允许再分发和导出的素材。快速建模不改变资产权限，也不将推测伪装成测量。参见[媒体规则](reference-media.md)与[渐进建模](progressive-modeling.md)。

每次迭代在三种视角检查受影响区域，保留移动、搜索和导航，验证来源及导出不变量和变更交互。先得到可检查的本地成果，再发布。记录改变、实际验证、未解决的不确定性与真实发布状态。通过长期开放维护逐步提升精度，不必等整张地图完成才允许交互。
