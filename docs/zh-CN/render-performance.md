# 稳定深度与不降质的性能评估

[English](../render-performance.md) | **简体中文**

先用固定镜头／输入路线测量已预热场景，记录源哈希、视口、像素比例、抗锯齿、人口、渲染后端、样本量、帧间隔及 CPU／GPU 分项。原生与人工压力测试分开；子系统加速不等于 FPS 同比提升，尤其已达刷新上限时。无头 Chrome、嵌入 WebView、真实手机可能有不同瓶颈。

## 单独诊断深度冲突

固定模型、材质、光照和镜头位置，只改 near，确认远处相近表面是否深度冲突。千米级 Overview 不宜一直沿用人物近景的极小 near。由静态地图包围盒及角色余量计算保守距离，仅在盒外空空间提高 near，向下量化以减少无谓投影更新。步行及盒内保留小 near。包围盒不包含跟随相机的天空；不冻结动态角色，新增高大／飞行实验时核验余量。

当前米制模板用 8 米余量、空距离的十分之一、64 米上限；近距离探索为 0.08 米，保留 FOV、透视与 far。覆盖常用视角和近景切换，不只看一张俯视图；无需重写建筑高度或简化屋顶。

参考 [PerspectiveCamera](https://threejs.org/docs/pages/PerspectiveCamera.html) 与[渲染器选项](https://threejs.org/docs/pages/WebGLRenderer.html#Options)：log depth 有 early-fragment-test 成本，reverse depth 有扩展依赖，更换深度后端前应核验设备和自定义 shader。

## 减少重复工作，保留内容

- 世界坐标标签采用独立小 CSS 场景，保留位置、投影、选中、边缘固定和更新频率，避免再次遍历建筑和动画骨骼。
- 静态地图最终摆放后计算一次 world 矩阵，只冻结明确静态根；动画／骨骼及独立活动角色保持更新。测试拾取、选择、相机遮挡及材质切换。[Object3D](https://threejs.org/docs/pages/Object3D.html) 说明关闭自动更新后的责任。
- 小地图显示输入精确不变时复用图像；归一化空路径，位置／方向／目标／路径变化和清空都失效。当前路径是不可变快照，修改应替换数组；不降低行走刷新频率。
- 不替换未变的 HUD 文字；评估期间保持几何、法线／颜色、分辨率、抗锯齿、光照及人口。

先检查已有优化，例如静态阴影可能本来就 autoUpdate=false，不能当作新增收益。稳态对比排除初次编译、上传和阴影渲染。GPU timer 需有效、非 disjoint；人工 CPU 限速下的排队时间不能视为设备 GPU 基准。

## 实验性静态雾缓存

viewer-settings.json 的 `cache_static_haze: true` 主动开启，默认关闭。最终静态摆放后由 `contextFog.bakeMesh` 把原逐顶点世界坐标雾场保存为一个 float 属性，保留插值、强度／颜色开关并兼容 PBR／Toon／颗粒 hook。共享几何但不同变换时独立缓存；骨骼、实例和 morph 输入不缓存。移动图层必须重算，不用于动态场景。

同一镜头／裁剪／材质／固定模拟状态比较动态与缓存路径，同时核验像素差和几何计数。计算每顶点一个 float 的 CPU／GPU 副本和载入成本。消费者实验图像差异极小，但 GPU 收益小且不稳定、内存增加可测，因此未作为默认优化；应在实际目标设备重新评估。

## 证据与归属

原始摘要和源哈希留在下游，大型本地 trace 不进公共素材库。测试专用源码注入只向独立测量页面开放检查引用，不增加公开调试 API 或统计。区分方案、实测子项收益和交付默认。

后续候选有保留拾取身份的同材质批处理、空间查询索引、保留全部几何的分块与视锥剔除；均可能权衡 CPU、绘制次数与内存。减面、动态分辨率、减少人口属于画质预算变化，另行决定。上游记录可复用方法，地点性能报告与开发日志仅在下游。
